# BOOGER ATLAS · 세계 코딱지 지질조사국

작은 표본을 진지하게 관측하는 한국어 시민 참여 웹앱입니다. React + TypeScript + Vite, Tailwind CSS, Leaflet, Recharts, Supabase, Open-Meteo로 구현했습니다.

**계정이나 API 키 없이 바로 실행할 수 있습니다.** 설정이 없으면 데모 모드가 켜지고, 기록은 해당 브라우저에만 저장됩니다. 실제 공동 수집은 본인의 Supabase 프로젝트를 연결한 뒤 시작합니다. 가상의 표본이나 통계는 초기 데이터에 포함하지 않았습니다.

## 1. 가장 빠른 실행

Node.js 22.12 이상을 설치하세요. 이 프로젝트는 Node.js 24.19에서 검증했습니다.

```bash
npm ci
npm run dev
```

터미널이 알려주는 로컬 주소를 브라우저에서 열면 됩니다. 환경변수 설정은 필요하지 않습니다. 개발 서버는 고정된 기상·지역 API에만 프록시를 제공하여 CORS와 클라우드 네트워크 환경을 처리합니다. Node.js 24.5 이상에서는 기존 HTTPS_PROXY 및 신뢰 CA 설정도 사용하며, TLS 검증을 끄지 않습니다. 빌드된 데모는 공개 HTTPS API, 실제 수집 모드는 Supabase Edge Function을 사용합니다.

- **관측 지도**: 세계 경계 지도, 지역 검색, 국가·지역별 실제 집계, 날짜 필터
- **표본 등록**: 지역·날짜·색상·크기·건조도 입력, 선택적인 GPS
- **지역 분석**: 색상·크기 분포, 날짜별 건조도·날씨 그래프, 오늘·내일 기상예보, 두 지역 비교

데모 기록은 새로고침해도 유지되지만 다른 브라우저나 기기에 공유되지 않습니다. 브라우저 저장소를 지우면 사라집니다. 데모 데이터를 실제 데이터베이스에 자동으로 옮기지 않습니다.

## 2. 실제 공동 수집 켜기 — 사용자가 할 일

외부 계정 생성과 배포는 자동으로 수행하지 않았습니다. 아래 작업이 필요합니다.

### A. Supabase 프로젝트와 데이터베이스

1. [Supabase](https://supabase.com/)에서 계정과 프로젝트를 만듭니다.
2. SQL Editor에서 `supabase/migrations/202610150001_atlas.sql` 전체를 한 번 실행합니다.
3. 프로젝트의 URL과 **공개 publishable 또는 legacy anon 키**를 확인합니다. `service_role` / secret 키는 브라우저에 절대 넣지 않습니다.

마이그레이션은 지역 5곳의 메타데이터만 추가합니다. 사용자 표본은 0개로 시작합니다. 원본 표본 테이블에는 RLS가 적용되어 익명 사용자의 직접 조회·삽입·수정·삭제가 모두 차단됩니다. Edge Function만 서버 권한으로 검증·저장·집계합니다.

### B. Edge Function 배포

프로젝트 루트에서 실행하세요. 로컬에서 Supabase 전체 서버나 Docker를 실행할 필요는 없습니다.

```bash
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
```

`supabase/functions/.env.example`을 같은 폴더의 `.env.local`로 복사하여 다음 세 값을 설정합니다. 이 파일은 Git에서 제외됩니다.

| 서버 환경변수      | 설정                                                                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `ALLOWED_ORIGINS`  | 허용할 웹앱 Origin을 쉼표로 구분. 개발 시 `http://localhost:5173,http://127.0.0.1:5173`, 배포 후 실제 HTTPS Origin 추가. 끝에 `/`를 붙이지 않음 |
| `IP_HASH_SECRET`   | 최소 32자 이상의 임의 비밀 문자열. IP를 일별 HMAC으로 변환하는 서버 전용 키                                                                     |
| `GEOCODER_CONTACT` | Nominatim 운영자가 연락할 실제 이메일 주소 또는 프로젝트 연락처 URL                                                                             |

비밀 문자열은 예를 들어 본인 터미널에서 아래 명령으로 생성해 서버 환경파일에 넣을 수 있습니다. 채팅이나 Git에 올리지 마세요.

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
npx supabase secrets set --env-file supabase/functions/.env.local
npx supabase functions deploy atlas --no-verify-jwt
```

`SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY`는 배포된 Supabase 함수에 기본 제공되는 서버 환경변수입니다. 프런트엔드 `.env`에 복사하지 않습니다. 인증 없는 시민 등록을 위해 JWT 검증을 끄고, 함수 안에서 입력 검증·요청 제한·허용 Origin 검사를 수행합니다. CORS 자체는 봇 인증 장치가 아닙니다.

CLI로 마이그레이션을 관리하려면 SQL Editor 실행 대신 `npx supabase db push`를 사용하세요. 같은 초기 마이그레이션을 두 방식으로 중복 실행하지 마세요.

### C. 웹앱 연결

루트 `.env.example`을 `.env`로 복사합니다.

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY
```

개발 서버를 재시작합니다. 배포 시에도 이 두 값을 빌드 환경변수로 등록하고 다시 빌드해야 합니다.

- 두 값 모두 비어 있으면 데모 모드입니다.
- 하나만 있거나 URL이 잘못되면 설정 오류를 표시합니다.
- 실제 연결 실패 시 성공 메시지를 띄우거나 데모 저장으로 전환하지 않습니다.
- Supabase가 연결되면 상단에 **공동 관측소**가 표시됩니다.

**연결 후 확인:** 표본 1건 등록 → 다른 브라우저에서 해당 지역·날짜 조회 → 같은 집계가 표시되는지 확인하세요. 개발 테스트 표본은 별도의 개발용 Supabase 프로젝트에서 만들고, 운영 프로젝트에는 실제 표본만 등록하세요.

## 3. 빌드와 정적 호스팅

```bash
npm run build
npm run preview
```

생성된 `dist/`를 Vercel, Netlify, Cloudflare Pages 등 정적 호스팅에 배포할 수 있습니다. 빌드 명령은 `npm run build`, 출력 폴더는 `dist`입니다. 화면 이동은 해시 라우팅을 사용하여 추가 서버 라우팅이 필요 없습니다. `public/_headers`는 지원하는 호스팅에서 기본 보안 헤더를 적용합니다. GPS는 HTTPS 또는 로컬 개발 주소에서만 동작합니다.

공개 배포와 Supabase 프로젝트 연결은 사용자가 수행해야 합니다. 현재 저장소 작성이나 로컬 검증은 인터넷 공개 배포를 의미하지 않습니다.

## 4. 지역 데이터와 개인정보

- 한국은 시·군·구급 경계만 선택할 수 있습니다. `동`·상세주소·가게 등은 검색 결과에서 제외합니다.
- 한국 공식 법정동 시군구 코드가 제공되면 `kr:legal:11680` 같은 ID를 사용하고, 그 외에는 `osm:relation:7444` 같은 안정적인 OpenStreetMap relation ID를 사용합니다.
- 강남구·마포구·종로구·해운대구·제주시는 실제 행정코드를 사용하는 기본 지역입니다. **지역이 존재한다는 의미이지 관측 표본이 있다는 의미가 아닙니다.**
- 세계 검색은 Nominatim에 있는 행정경계를 이용합니다. 기본적으로 OSM admin level 6~8을 수용하며 뉴욕시처럼 level 5인 해외 도시도 허용합니다. 국가별 체계가 달라 모든 지역을 완전히 지원하지는 않습니다. 국가·주만 있는 결과, 상세 동네, 식별 가능한 경계가 없는 지역은 선택하지 않습니다.
- 같은 이름의 행정단계가 여러 개면 결과의 국가·상위 행정구역·경계 level을 확인하세요. 지역 이름은 공급자가 제공하는 한국어 이름을 우선하고, 없는 경우 현지 이름을 표시합니다.
- GPS는 버튼을 클릭한 경우에만 권한을 요청합니다. 거부해도 검색과 빠른 선택으로 계속 등록할 수 있습니다.
- GPS 좌표는 행정구역 식별을 위해 Nominatim으로 일시 전송됩니다. 실제 모드에서는 Edge Function을 경유합니다. 역검색 후 행정경계 대표 좌표를 다시 조회하며, **사용자 GPS·상세 주소·원본 요청 본문을 DB나 브라우저 저장소에 저장하지 않습니다.**
- 지도 점은 행정구역 대표 지점입니다. 개인 위치가 아닙니다.
- 웹 호스팅/외부 API의 인프라 접속 로그는 앱 데이터베이스와 별개이며 해당 사업자의 정책을 따릅니다.

지도·지역·기상자료의 출처와 라이선스는 `public/DATA-SOURCES.md`에 정리했습니다. 기본 지도는 프로젝트에 포함된 Natural Earth 세계 경계로 그리므로 외부 지도 타일을 다운로드하지 않습니다.

## 5. 날씨 연결과 데이터 해석

모든 날씨는 **선택한 행정구역의 대표 좌표**로 조회합니다. 개인 좌표를 사용하지 않습니다.

| 종류          | 처리                                                                       |
| ------------- | -------------------------------------------------------------------------- |
| 오늘·내일     | Open-Meteo Forecast API, 해당 지역의 시간대 기준 일평균 기온·습도·일강수량 |
| 5일 이전 과거 | Open-Meteo Archive API의 ERA5 재분석 자료                                  |
| 최근 과거     | Forecast API의 최근 과거 모델 자료                                         |
| PM2.5 / PM10  | Air Quality API에서 제공되는 날짜만 조회, 범위 밖이거나 오류면 `자료 없음` |
| 누락·장애     | 값을 추측하거나 0으로 바꾸지 않고 `자료 없음` 처리                         |

과거 재분석 자료도 측정소의 직접 실측값과 같지는 않습니다. PM 자료 역시 모델 자료입니다. 그래프에는 서로 다른 단위를 구분하여 표시하고 데이터 표도 제공합니다. 기온은 별도 축이므로 선의 교차나 기울기를 직접 비교하면 안 됩니다.

- 분석 그래프는 선택 기간의 관측값을 모두 표시합니다. 외부 호출량을 줄이기 위해 기상자료 자동 연결은 최근 관측일 14개로 제한합니다. 다른 관측일은 **관측일 기상자료 개별 조회**에서 확인할 수 있습니다.
- 캐시: 지역 ID + 날짜 기준. 과거 확정에 가까운 자료는 30일, 최신/예보는 1시간. 실제 모드의 공급자 장애는 2분 동안 짧게 캐시합니다. 동시 프런트엔드 요청도 합칩니다.
- 데모 캐시는 브라우저, 실제 캐시는 Supabase DB에 저장합니다.
- 지역 검색도 캐시하며, 자동완성 요청을 보내지 않고 검색 버튼/Enter에서만 조회합니다. 실제 서버는 Nominatim 전체 호출을 원자적 DB 슬롯으로 1.1초 간격 제한합니다.
- 무료 Nominatim과 Open-Meteo에는 이용량/용도 조건이 있습니다. 대규모 또는 상업 운영 시 공급자의 현재 요금·정책에 맞는 엔드포인트로 전환해야 합니다.

코딱지 전망에는 최근 30일의 실제 최빈 색상·크기와 평균 건조도만 표시합니다. 데이터가 있어도 **과학적으로 검증되지 않은 코딱지 예측은 제공하지 않습니다.** 동률은 UI에 명시된 표시 순서를 따릅니다.

## 6. 데이터 구조와 보안

| 테이블                | 용도                                                              |
| --------------------- | ----------------------------------------------------------------- |
| `atlas_regions`       | 고유 지역 ID, 이름, 국가·상위 지역, 행정 대표 좌표, 출처          |
| `atlas_observations`  | 비공개 원본 표본. 임의 UUID, 지역 ID, 발견 날짜, 색상·크기·건조도 |
| `atlas_api_cache`     | 날씨·지역 검색 캐시                                               |
| `atlas_rate_limits`   | 원본 IP를 남기지 않는 요청 제한용 해시·횟수·만료시각              |
| `atlas_service_slots` | Nominatim 전체 요청 간격 조정                                     |

공개 API는 `atlas` Edge Function 한 개입니다. `stats` 응답은 지역·날짜·특징별 **집계 count**이며 원본 표본 ID·등록 시각·IP 해시는 반환하지 않습니다. 사용자 식별정보를 수집하지 않으므로 1건만 있는 지역도 지역 통계로 표시할 수 있습니다.

- 서버에서 필수값, 실제 존재하는 지역, 색상·크기 enum, 정수 건조도, 날짜 범위, UUID를 재검증합니다.
- 클라이언트는 사용자 현지 날짜, 서버는 전 세계 시간대를 수용하는 UTC+14의 오늘까지 허용합니다. 1940년 이전은 기상자료 범위에 맞춰 허용하지 않습니다.
- 동일 UUID 재시도는 멱등 처리합니다.
- 실제 등록 제한: IP 기반 일별 HMAC 식별자로 10분 5건, UTC 일자별 30건. 전체 API 1분 90회, 검색 1분 20회, 기상 1분 40회.
- 최소 체류시간 800ms와 숨겨진 입력 필드(honeypot)가 단순 자동 등록을 억제합니다. 완전한 봇 방어는 아니며, 대규모 악용 대응용 CAPTCHA는 후속 기능입니다.
- Supabase 게이트웨이가 설정하는 `X-Forwarded-For`의 마지막 값을 사용합니다. 다른 호스팅으로 옮기면 신뢰할 프록시 헤더를 확인해야 합니다. 헤더가 없으면 공유 `unknown` 버킷으로 제한합니다.
- 만료 항목은 `select public.atlas_cleanup();`으로 제거할 수 있습니다. Supabase Cron에서 하루 한 번 실행하도록 등록하면 만료된 해시·캐시가 정리됩니다. 보관할 개인별 상세 데이터는 없습니다.

클라이언트가 보내는 지역 좌표나 임의 지역 객체를 서버가 저장하지 않습니다. 지역은 서버의 검색 결과나 사전 등록된 실제 행정구역만 받아들입니다. 서비스 역할 키는 Edge Function 환경에만 존재합니다.

## 7. 테스트

```bash
npm test             # 입력/통계/기상 및 실제 PostgreSQL 엔진(PGlite) 마이그레이션·RLS 검증
npm run test:e2e     # Chromium 데스크톱 + 모바일 브라우저 흐름
npm run build       # TypeScript 검사 + 프로덕션 빌드
```

브라우저 테스트는 시스템 Chromium이 있으면 사용합니다. 없으면 먼저 `npx playwright install chromium`을 실행하세요. 별도 경로가 필요하면 `CHROMIUM_PATH`를 설정합니다. 테스트 데이터는 테스트 브라우저와 메모리 PostgreSQL에만 생성되어 실제 사용자 DB와 분리됩니다.

검증 범위: 빈 지도, 필수항목 누락, 미래·잘못된 날짜, GPS 거부와 수동 선택, 해외 행정구역 필터, API 장애, 기록 유지, 날짜 필터, 통계, 모바일 가로 넘침, DB 접근제어와 제한. 외부 API 장애 테스트는 고정 응답으로 재현하며, 실제 외부 연결 확인은 별도로 진행했습니다. 자세한 실행 결과는 `VALIDATION.md`를 참고하세요.

Edge Function 타입 검사는 Deno 2가 있을 때 실행할 수 있습니다.

```bash
deno check supabase/functions/atlas/index.ts
```

## 8. 구조

```text
src/
  App.tsx                 # 세 화면 연결, 공통 상태, 관측 지도 화면
  pages/                  # 기록·지역 분석
  components/             # 지도·지역 검색·분포·그래프·기상 패널
  lib/api.ts              # 데모 / Supabase 전환, 저장·검색·캐시
  styles.css              # Tailwind 진입점과 반응형 디자인
supabase/
  migrations/             # 테이블, RLS, 집계·요청 제한 함수
  functions/atlas/         # 단일 서버 API
  functions/_shared/      # 브라우저/서버 공용 모델·검증·기상 어댑터
public/world.geojson      # 실제 세계 경계 기초자료
tests/                   # 단위·DB·브라우저 테스트
```

코딱지 예측 모델은 지역·날짜별 통계와 기상 캐시를 입력으로 사용할 수 있도록 분리되어 있습니다. 향후 충분한 데이터, 학습/검증 분리, 편향 평가를 갖춘 뒤 새로운 분석 모듈로 추가할 수 있습니다. 현재 예측 모델이나 과학적 유효성 검증은 구현하지 않았습니다.

이번 MVP에는 로그인, 개인 프로필, 포인트, 랭킹, 암호화폐, 결제, 사진 분석을 넣지 않았습니다. 실제 Supabase 계정 연결·공개 배포, 모든 국가의 행정단계 정규화, 고급 봇 방어, 대규모 통계 페이지네이션은 후속 작업입니다.
